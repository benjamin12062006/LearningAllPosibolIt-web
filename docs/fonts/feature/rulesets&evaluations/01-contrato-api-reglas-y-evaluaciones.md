## Interpretación y límites

- **No existe un listado de evaluaciones.** Solo se lee una evaluación por su id. La web no puede mostrar un historial sin un endpoint nuevo en la API o sin guardar ids por su cuenta.
- `errores.csv` exige `Authorization`: un enlace `<a href>` no envía el token. Hay que pedirlo con el cliente y descargar el contenido recibido.
- Los issues de reglas señalan una **fila** del formulario (un atributo del mapeo o una regla), no un campo concreto: el último segmento de `rules.<i>.<atributo>` es el atributo usado, no una propiedad de la regla.
- `findRulesetIssues` es lógica de la API. Repetirla en la web daría aviso inmediato, pero dos copias pueden divergir.
- El árbol de la API está en obras (organizaciones, feeds). Si cambian estos contratos, hay que revisar esta ficha antes de implementar.
